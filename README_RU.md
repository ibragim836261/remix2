# LANControl KZ — iOS-проект

Приложение на SwiftUI для управления своей домашней Wi‑Fi сетью. Проект рассчитан на iPhone/iPad, iOS 16+.

## Что уже есть в проекте

- Главный экран состояния роутера и счётчики устройств/блокировок.
- Настройки локального адреса, логина, пароля, провайдера и производителя.
- Хранение пароля администратора в iOS Keychain, а не в обычных настройках приложения.
- Встроенная веб-панель роутера через `WKWebView`.
- Список устройств из поддерживаемых Keenetic/Netcraze RCI-ответов.
- Чёрный список с реальной командой запрета/разрешения доступа на Keenetic и обязательным чтением состояния обратно перед подтверждением действия.
- Родительский раздел: пометка детских устройств, немедленная блокировка/разблокировка, выбор уже созданного в роутере расписания для устройства.
- Профили провайдеров Казахстана: Beeline Kazakhstan, Казахтелеком, Tele2/Altel, AlmaTV, Transtelecom, Freedom Telecom и «Другой».
- Каталог производителей: Keenetic, Huawei, ZTE, TP-Link, ASUS, MikroTik, Xiaomi, D-Link, Nokia, FiberHome, Sercomm, Sagemcom, Tenda, Mercusys, Netis, Ubiquiti, Zyxel, Cudy, Totolink, Linksys, H3C, Ruijie.
- Интерфейс RU/KZ/EN (часть технических сообщений и текста совместимости остаётся на русском).
- Запрос только релевантного разрешения iOS на локальную сеть.

## Важное о совместимости

**Реальное автоматическое управление сейчас реализовано для Keenetic/Netcraze с доступным RCI API.** Приложение регистрирует устройство, отправляет запрет/разрешение, затем читает конфигурацию обратно. Если роутер не подтвердил результат, приложение сообщает об ошибке и не выдаёт ложный статус.

Для Beeline Kazakhstan, Казахтелекома и остальных провайдеров есть профиль провайдера и список производителей, но провайдер не определяет API: у абонентов встречаются разные модели и прошивки. Для Huawei CPE производитель документирует собственный родительский контроль; у TP-Link есть Access Control. В этом проекте для них открывается веб-панель, а действия нужно выполнить в интерфейсе самого роутера. Универсальная автоматическая блокировка ZTE/Huawei/TP-Link/любого роутера не заявляется.

Для расписания в родительском разделе используется список расписаний, уже созданных на поддерживаемом Keenetic. Создание сложных расписаний в самом роутере из приложения пока не включено. Создай расписание в панели роутера, обнови список и назначь его детскому устройству.

## Установка и подключение

1. Подключи iPhone к Wi‑Fi управляемого роутера.
2. Открой LANControl KZ → Настройки.
3. Укажи локальный адрес роутера (обычно `192.168.1.1` или `192.168.0.1`), логин и пароль администратора.
4. Выбери провайдера и фактический бренд роутера. Для Keenetic выбери Keenetic/Netcraze или Автоопределение.
5. Нажми «Сохранить настройки» и «Подключиться».
6. При первом обращении к локальной сети iOS покажет системный запрос. Разреши доступ: без него управление роутером не работает.
7. Для Huawei/TP-Link/прочих моделей открой «Панель роутера» и используй штатный раздел контроля доступа/родительского контроля.

Не вводи пароль администратора роутера на чужих устройствах и не используй приложение для сетей, которыми ты не управляешь.

## Сборка на macOS

Требуется macOS с Xcode 16 или новее.

```bash
xcodebuild -project NetControlKZ.xcodeproj \
  -scheme NetControlKZ \
  -configuration Release \
  -sdk iphoneos \
  -derivedDataPath build \
  CODE_SIGNING_ALLOWED=NO build

./scripts/package_ipa.sh build/Build/Products/Release/NetControlKZ.app
```

Скрипт соберёт `LANControlKZ-unsigned.ipa` с `Payload/NetControlKZ.app`. IPA без подписи не является готовым подписанным релизом: его нужно импортировать/подписать штатным способом в SideStore или собрать с собственной Apple signing identity. В архиве нет чужих сертификатов, provisioning profiles или Apple ID.

## GitHub Actions

Workflow `.github/workflows/ios-build.yml` собирает проект на macOS runner и публикует unsigned IPA как CI artifact. Этот репозиторий/архив нужно загрузить в GitHub и запустить workflow через Actions.

## Разрешения iOS

Приложение использует только локальную сеть для подключения к роутеру. В `Info.plist` добавлено `NSLocalNetworkUsageDescription` и локальное ATS-исключение для HTTP панели роутера. Не запрашиваются геолокация, камера, микрофон, контакты, Bluetooth или multicast entitlement: для текущего подхода они не нужны. Системное разрешение локальной сети пользователь подтверждает сам в iOS.

## Ограничения

- Список всех клиентов нельзя гарантированно получить универсальным iOS-сканированием; приложение использует данные роутера через его API.
- Некоторые Keenetic endpoints и поля зависят от версии KeeneticOS и набора компонентов. Для тестирования нужен физический роутер.
- Самостоятельная сборка IPA требует macOS/Xcode. Текущая среда сборки — Linux, поэтому этот архив содержит исходный Xcode-проект, а не проверенный бинарный IPA.
- Проект не реализует ARP spoofing, MITM, сетевые атаки, обход пароля или отключение чужих устройств.

## Ручная настройка роутера и MAC
В настройках можно указать полный URL роутера (например, `http://192.168.1.1`), модель, логин и пароль. Встроенный браузер WKWebView имеет адресную строку, поэтому можно перейти на другой адрес локальной панели и войти в неё прямо внутри приложения. На вкладке «Чёрный список» есть ручное поле MAC. Для Keenetic используется проверенная интеграция проекта; для остальных производителей пользователь добавляет MAC в штатном разделе Access Control / Blacklist внутри встроенного браузера, если модель предоставляет такую функцию. Приложение не заявляет об успешной блокировке, пока роутер не подтвердил действие.
